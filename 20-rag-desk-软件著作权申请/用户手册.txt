1  引言
================================================================================

1.1  编写目的
--------------------------------------------------------------------------------
  本手册面向系统管理员、运营人员和普通用户，说明 RAG-Desk 垂直行业知识库
  问答系统 V1.0 的安装、配置、日常操作与常见问题处理方法，同时也是软件著作
  权登记申请的依据文档之一。

1.2  软件概述
--------------------------------------------------------------------------------
  RAG-Desk 是一套面向律所、诊所、招采等垂直行业的本地化知识问答系统。它把
  机构公开资料（Markdown、PDF、DOCX、TXT、CSV）导入本机 SQLite 全文索引，
  用户提出问题后，系统在离线环境下从知识库检索最相关的原文片段，给出带来源
  引用的回答。

  主要特点：
    · 完全离线：默认不依赖任何外部大模型或向量数据库，数据不出机器；
    · 中文友好：针对中文短查询优化的分词与相关度排序；
    · 可溯源：每条回答附文档名、段落号与原文摘录；
    · 易嵌入：一段 script 标签即可把问答浮窗嵌入任意网站；
    · 轻量化：Node.js ≥ 22.5 单进程运行，SQLite 内嵌，无独立数据库服务。

1.3  读者对象与使用约定
--------------------------------------------------------------------------------
  读者对象：系统部署人员（管理员）与终端使用者（前台/客服/访客）。
  约定：代码与命令以等宽字体给出；“→”表示界面路径；“[ ]”内为可选项；
  花括号表示需要替换的内容。

2  安装与卸载
================================================================================

2.1  运行环境要求
--------------------------------------------------------------------------------
  - 操作系统：Linux / macOS / Windows（x86-64 或 arm64）；
  - 运行时：Node.js ≥ 22.5.0（需内置 node:sqlite 模块，无需额外编译本地
    依赖；Windows 下建议 Node 官方预编译二进制）；
  - 内存：建议 ≥ 2GB（最低 512MB）；
  - 浏览器：Chrome / Edge / Firefox / Safari（现代版本）访问前后台页面；
  - 可选：Docker Engine 20.10+ 与 Docker Compose。

2.2  安装步骤（源码方式）
--------------------------------------------------------------------------------
  第 1 步：确认 Node 版本
      node --version        （应 ≥ v22.5.0）
  第 2 步：进入项目目录并安装依赖
      cd 20-rag-desk
      npm install
  第 3 步：（可选）生成并导入演示语料
      npm run seed
  第 4 步：启动服务
      npm start
  启动成功后控制台会打印访问地址，默认端口 3000。

2.3  安装步骤（Docker 方式）
--------------------------------------------------------------------------------
  第 1 步：在项目根目录执行
      docker compose up --build
  第 2 步：访问 http://localhost:3000
  说明：镜像多阶段构建（npm ci + 运行）；数据持久化于命名卷 ragdesk-data，
  容器重建后数据不丢失；镜像配置了 /api/health 健康检查。

2.4  首次启动与演示数据
--------------------------------------------------------------------------------
  首次启动（源码或 Docker）时，系统会自动检测数据库是否已初始化；若未初始化
  且数据目录存在演示语料，会自动写入一版中文领域语料（法律/诊所/招采公告
  等），保证初次打开即能演示问答。可通过 RAGDESK_DB 改变数据库路径，或用
  npm run seed 手动重置。

2.5  卸载说明
--------------------------------------------------------------------------------
  - 源码方式：停掉进程（Ctrl+C 或 kill）后删除项目目录即可；数据目录
    data/ragdesk.db 一并删除即清除全部索引与日志。
  - Docker 方式：docker compose down；如需彻底删除数据卷执行
    docker compose down -v（注意：-v 会删除 ragdesk-data 卷内全部数据）。

3  操作说明
================================================================================

3.1  演示问答页
--------------------------------------------------------------------------------
  访问 http://localhost:3000/：
  - 页面中部为聊天窗口；在底部输入框输入问题，回车或点击发送；
  - 回答会附上“引用来源”，展示命中的文档名、段落号与原文摘录；
  - 可切换领域（法律/医疗/招采/通用），切换后问候语与话术随之变化；
  - 点击示例问题可直接提问。
  示例提问：
    · 律师咨询费怎么收取？
    · 挂号需要带什么？
    · 儿童接种疫苗时间？

3.2  管理后台
--------------------------------------------------------------------------------
  访问 http://localhost:3000/admin：
  - 后台首页展示已索引文档列表（文件名、类型、分块、大小、上传时间）；
  - 点击文档可查看其全部索引分块内容（用于核验收割与检索效果）；
  - 顶部提供上传区与查询统计卡片。
  注意：若部署时设置了 RAGDESK_ADMIN_TOKEN，首次进入后台会要求输入访问
  令牌（x-admin-token）；输入后会话内生效。

3.3  文档上传与索引管理
--------------------------------------------------------------------------------
  上传：后台点击“上传”选择文件（可多选，支持 .md/.txt/.csv/.pdf/.docx），
  单文件不超过 50MB、单次不超过 20 个；系统自动解析→分块→索引，并逐文件
  返回结果（indexed/duplicate/error）。
  删除：在文档列表点击删除按钮，可移除文档及其全部分块与索引；删除后相关
  引用即不再命中。
  去重：对同一文件重复上传，系统按内容摘要自动识别并返回 duplicate，不会
  建立重复索引。

3.4  查询日志与统计
--------------------------------------------------------------------------------
  后台“统计”区展示：
  - 总查询量（total）；
  - 有回答命中量（with_answer）与命中率；
  - 最近查询记录（问题、时间、命中数、来源文档）。
  可用于运营分析：哪些问题高发、哪些文档被检索命中最多，据此补充语料。

3.5  嵌入式浮窗（widget）
--------------------------------------------------------------------------------
  在任意网页中引入：

  <script
    src="http://localhost:3000/widget.js"
    data-api="http://localhost:3000/api/chat"
    data-domain="medical"
    data-title="诊所在线咨询"
    data-greeting="您好，我是诊所在线导诊助手。"></script>

  页面右下角会出现悬浮聊天按钮，点击展开/收起；用户提问即调用 data-api 指定
  的问答接口。跨域访问由服务器端 RAGDESK_ALLOW_ORIGIN 控制；如设置了
  RAGDESK_CHAT_TOKEN（例如 abc123），请在 script 标签上增加浮窗配置项
  data-token="abc123"，浮窗会自动在请求头携带
  Authorization: Bearer abc123。

3.6  HTTP 接口调用示例
--------------------------------------------------------------------------------
  健康检查：
      curl http://localhost:3000/api/health
  问答：
      curl -X POST http://localhost:3000/api/chat \
        -H "Content-Type: application/json" \
        -d '{"query":"律师咨询费怎么收取？","domain":"legal"}'
  若设置了聊天令牌（如 abc123），请求头附：Authorization: Bearer abc123。
  上传：
      curl -X POST http://localhost:3000/api/admin/upload \
        -H "x-admin-token: change-me" \
        -F "files=@./fixtures/corpus/clinic-faq.md"
  删除：
      curl -X DELETE http://localhost:3000/api/admin/docs/1 \
        -H "x-admin-token: change-me"

4  配置与参数
================================================================================

4.1  环境变量
--------------------------------------------------------------------------------
  变量名              默认值        说明
  PORT               3000          HTTP 监听端口。
  RAGDESK_DB         data/ragdesk.db  SQLite 数据库文件路径。
  RAGDESK_ADMIN_TOKEN 空（开放）   设置后 /api/admin/* 需 x-admin-token 请求头；
                                   docker-compose.yml 中默认 change-me，请替换。
  RAGDESK_CHAT_TOKEN  空（开放）   设置后 /api/chat 需 Authorization: Bearer。
  RAGDESK_ALLOW_ORIGIN 跟随 Origin  限制浮窗跨域来源：* 或具体站点，如
                                   https://docs.example.com。

  示例（Linux/macOS）：
      PORT=8080 RAGDESK_DB=/var/lib/ragdesk.db npm start
  示例（Windows PowerShell）：
      $env:PORT=8080; $env:RAGDESK_DB="D:\data\ragdesk.db"; npm start

4.2  领域模板自定义
--------------------------------------------------------------------------------
  在 src/lib/domains.js 中新增领域条目即可，例如：
    { id:'school', label:'教育 · 学校',
      greeting:'您好，我是校园信息助手。',
      lead:'根据校园资料，以下相关内容供参考：',
      fallback:'抱歉，校园知识库中暂无相关内容，请咨询教务处。',
      footer:'（信息以学校官方发布为准。）',
      systemPrompt:'你是一名校园客服助手。仅依据上下文原文回答。',
      exampleQuestions:['报到需要带哪些材料？'] }
  保存后重启服务；问答页领域列表与 /api/domains 会自动更新。

4.3  可选 LLM 摘要
--------------------------------------------------------------------------------
  系统默认关闭 LLM 摘要（/api/health 中 llmEnabled=false）。如需启用，由调用
  方自行注入 summarizer 函数：其入参为 { query, context, systemPrompt }，返回
  文本回答。内置 mockSummarizer 仅用于功能演示与测试，不代表真实模型能力。

5  故障处理与常见问题（FAQ）
================================================================================

5.1  启动故障
--------------------------------------------------------------------------------
  Q1 启动报 “Cannot find module 'node:sqlite'”？
  处理：Node.js 版本低于 22.5。升级 Node 至 ≥ 22.5 后重试（node --version
  检查）。
  Q2 提示端口被占用 / EADDRINUSE？
  处理：更换端口（PORT=8080 npm start），或结束占用进程。
  Q3 Docker 构建慢 / 失败？
  处理：多为网络问题；可配置国内 npm 镜像（Dockerfile 内 npm config set
  registry），或先在本机 npm install 缓存。

5.2  检索/问答异常
--------------------------------------------------------------------------------
  Q4 问题答非所问 / 命中不准？
  处理：知识库中是否包含相关内容；中文短查询建议≥2 个汉字；补充或修正资料
  后重新上传覆盖。可在后台查看该文档分块确认索引是否完整。
  Q5 返回“抱歉，我在知识库中暂未找到与您问题直接相关的内容。”？
  处理：属正常兜底。换一种问法（提取核心关键词）重试，或先上传相关资料。
  Q6 偶发检索语法异常告警？
  处理：系统已内置自动降级（LIKE 扫描），一般不影响使用；多为含特殊符号的
  输入触发。

5.3  上传与索引问题
--------------------------------------------------------------------------------
  Q7 上传返回 “不支持的文件类型”？
  处理：支持 .md/.markdown/.txt/.csv/.pdf/.docx；请上传上述格式。
  Q8 上传报 “文件内容为空，无法索引”？
  处理：文件内容为空或全空白；补充正文后重传。
  Q9 上传 400/413 错误？
  处理：超过单文件 50MB 或单批 20 个限制；拆小后分批上传。
  Q10 某 PDF 乱码 / 解析为空？
  处理：多为扫描件（图片型）PDF，无文字层；请提供文字版 PDF 或转为
  .txt/.md 上传。

5.4  安全与部署问题
--------------------------------------------------------------------------------
  Q11 后台提示 “unauthorized”？
  处理：未携带正确的 x-admin-token；检查请求头与 RAGDESK_ADMIN_TOKEN 是否
  一致，并确认 docker-compose 中已替换默认 change-me。
  Q12 网页浮窗跨域被拦截？
  处理：按需设置 RAGDESK_ALLOW_ORIGIN（* 或站点白名单）；如对同一站点失效
  请检查 data-api 地址与浏览器无痕缓存。
  Q13 数据会被上传到云端吗？
  处理：不会。默认路径完全离线，只读本地 SQLite；请勿在同一实例上启用
  外部 summarizer（涉及外发数据时数据会离开本机）。

5.5  性能建议
--------------------------------------------------------------------------------
  - 语料规模增大后，定期用 DELETE 移除过时文档并重新上传，控制分块总量；
  - 保持机器闲置内存充足（SQLite 读缓存）；
  - 若单机负载过高，与应用整体水平扩展相比，更稳妥的路线是拆分知识库
    （多个实例各管一个领域/库），并通过 widget 的 data-api 分流。
