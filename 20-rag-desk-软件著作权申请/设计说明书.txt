1.1  编写目的
--------------------------------------------------------------------------------
  本说明书描述 RAG-Desk 垂直行业知识库问答系统 V1.0（以下简称“本系统”）的
  总体设计与详细设计，供软件著作权登记审核、程序维护、二次开发及测试人员
  理解本系统的体系结构与实现机理。
  本说明书面向的对象：软件著作权登记审查人员、本系统后续维护与开发人员。

1.2  项目背景
--------------------------------------------------------------------------------
  随着律所、诊所等垂直行业知识存量日益增长，人工客服难以覆盖高频重复咨询。
  本系统面向上述场景，提供一套完全离线、可嵌入、可溯源的本地知识问答方案：
  将行业资料（Markdown/PDF/DOCX/TXT/CSV）导入本机，经中文友好的全文检索与
  相关度排序，自动回答用户提问并给出可核查的原文引用，数据始终驻留本机，
  不依赖任何外部大模型或向量数据库。

  项目名：RAG-Desk（垂直行业 RAG 客服壳）。
  软件简称：RAG-Desk；软件全称：RAG-Desk 垂直行业知识库问答系统。
  版本：V1.0；开发完成日期：2026-11-16；开发方式：独立开发。

1.3  定义
--------------------------------------------------------------------------------
  项次   术语          说明
  RAG    Retrieval-Augmented Generation，检索增强生成。
  FTS5   SQLite 内置的全文检索扩展，支持 BM25 相关度排序。
  bigram 二元切词，将连续中文字符串切成相邻二字的词元。
  BM25   经典概率检索排序模型，用于计算查询与文档片段的相关度。
  分块   将长文档按窗口与段落切分为相互独立但带有重叠的检索单元。
  倒排表 FTS5 内部按词元建立的“词元—文档/行”映射索引结构。

2  总体设计
================================================================================

2.1  需求规定
--------------------------------------------------------------------------------
  2.1.1 功能需求
    FR1 知识摄入：支持 Markdown、TXT、CSV、DOCX、PDF 的导入与入库；自动
         分块；重复文档（按内容 SHA-256）幂等处理，不重复索引。
    FR2 中文检索：支持中文短查询（2~3 字）命中；按 BM25 相关度返回 Top-N
         知识片段及其来源文档与段落号。
    FR3 离线问答：给出“引导语 + 检索原文摘录 + 兜底语”的答案；附置信度
         与引用列表；不依赖外部 LLM/embedding。
    FR4 领域适配：内置法律、医疗、招采、通用四套话术模板与示例问题。
    FR5 管理后台：文档列表、分块预览、删除、批量上传、查询日志与统计。
    FR6 嵌入能力：widget.js 可在第三方站点嵌入聊天浮窗；支持跨域与鉴权。
    FR7 查询记录：每次问答写入日志，供统计命中率与追溯。
  2.1.2 性能需求
    单机千级文档、十万级分块量级下，查询 P95 响应 < 300ms（SQLite FTS5
    本地检索）；单文件上传上限 50MB；单次上传文件数 ≤ 20。
  2.1.3 可靠性需求
    事务化入库（BEGIN IMMEDIATE/COMMIT/ROLLBACK），入库失败不残留脏数据；
    查询语法异常自动降级为 LIKE 扫描；解析失败仅报告该文件，不影响其余。
  2.1.4 安全需求
    管理端令牌（x-admin-token）、聊天端 Bearer 令牌（Authorization）可选
    校验；跨域来源可由 RAGDESK_ALLOW_ORIGIN 限制；数据不出机器。

2.2  运行环境
--------------------------------------------------------------------------------
  硬件：x86-64 / arm64 单机，内存 ≥ 512MB（推荐 2GB）。
  软件：Node.js ≥ 22.5.0（内置 node:sqlite，无需编译本地依赖）；Linux /
       macOS / Windows；数据库 SQLite（WAL 模式 + FTS5 扩展）。
  前端：现代浏览器（Chrome / Edge / Firefox / Safari）。
  部署：Docker Engine + Docker Compose（镜像内置 node 运行环境）。

2.3  基本设计概念和处理流程
--------------------------------------------------------------------------------
  2.3.1 核心设计理念
    (1) 离线优先：检索回答全链路在本地完成，无外部 API 调用；LLM 摘要为
        可选开关（默认关闭），注入自制 summarizer 函数即可启用。
    (2) 中文友好：SQLite FTS5 默认分词（unicode61）不能切分中文，本系统在
        写入索引前将每段文字中的汉字连续区扩展为二元词元，查询时同样将
        中文查询扩为 OR 模式二元词，使短中文查询可命中、BM25 可排序。
    (3) 索引与原文分离：FTS 表仅存“扩展词元 + 原始文本（UNINDEXED）”；
        原文字段用于摘录与回显，词元用于检索，避免中文分词信息损失。
    (4) 可溯源：答案与引用均取自真实入库片段，每段携带文档名与段落号。
  2.3.2 数据流（摄入）
    文档文件（Buffer）→ 扩展名判定 fileKind → 按格式解析出纯文本 →
    chunkText 分块（段落感知 + 400 字符窗口 + 40 字符重叠）→ 计算 SHA-256
    → 与 docs 表查重 → 插入 docs（元数据）→ 插入 chunks（正文）→ 对每个
    分块 expandForIndex 生成词元串，写入 fts（tokens, orig）。
  2.3.3 数据流（问答）
    用户提问 → toQuery 构造 FTS5 MATCH 表达式 → fts 检索取 Top-N →
    按行联系回 chunks/docs 元数据 → confidenceScore 计算置信度 →
    excerptFrom 生成带关键词锚定的摘录 → 组装 answer（lead+摘录+footer）
    → 写 queries_log → 返回 JSON。
  2.3.4 模块关系图（文字表述）
    server.js ──> app.js ──> knowledge.js ──> storage.js ──> node:sqlite
                               │   │    │
                               │   │    └──> tokenizer.js
                               │   └──────────> chunker.js
                               └──────────────> extractors.js
    app.js ──> domains.js（话术模板）
    server.js ──> scripts/seed-fixtures.js（首次种子语料）

2.4  结构（模块划分）
--------------------------------------------------------------------------------
  本系统按“表现层—服务层—数据层”分层：

  ┌─ 层        ── 模块               ── 职责
  ├─ 表现层      public/*（HTML/JS/CSS） 演示页、管理后台、widget.js
  │             app.js 静态路由         托管页面与脚本
  ├─ 服务层      app.js 路由             /api/chat、/api/admin/*、/api/health
  │             knowledge.js            摄入、检索、答案组装
  │             chunker.js              分块
  │             tokenizer.js            分词与查询构造
  │             extractors.js           文档解析
  │             domains.js              领域模板
  ├─ 数据层      storage.js             统一访问 node:sqlite
  │             SQLite 数据库           docs/chunks/fts/queries_log/settings
  └─ 入口        server.js              启动、端口、首次种子

  全部代码为 JavaScript（Node.js ≥ 22.5，CommonJS），无构建步骤。

3  详细设计
================================================================================

3.1  模块 01：chunker（src/lib/chunker.js，有效 48 行）
--------------------------------------------------------------------------------
  功能：将纯文本划分为检索单元。
  算法：
    (1) 去除首尾空白；空文本返回 []。
    (2) 按单换行切分为“段落”（保留 Markdown 列表/问答块等行级结构）。
    (3) 若全文无换行（单一长段），按窗口 400 + 重叠 40 直接滚动切窗；
        切槽优先落在句号/问号/感叹号等句界（[。！？!?；;]）之后。
    (4) 否则逐段处理：超窗段落先单独 emitRun（重叠切窗）；短段落并入缓冲
        至接近窗口上限后输出；最终清空缓冲。
    (5) 输出有序数组 [{ index: 1..n, text }]。
  入参：text, opts{window=400, overlap=40}；出参：chunk 数组。
  主要函数：chunkText(text, opts)。

3.2  模块 02：tokenizer（src/lib/tokenizer.js，有效 70 行）
--------------------------------------------------------------------------------
  功能：中文友好分词与 FTS5 查询/索引互转。
  关键常量和函数：
    CJK_RE  ：中文字符范围正则（\u3400-\u4dbf、\u4e00-\u9fff、\uf900-\ufaff）。
    DELIM_RE：标点/符号/控制字符（\p{P}\p{S}\p{C}）作为分隔符。
    normalize(text)：转小写、压缩空白。
    tokenize(text)：将文本切为 {kind:'cjk'|'other', token} 序列。
    ngrams(run, n=2)：对汉字连续区生成重叠二元词元。
    toQuery(text)：构造 MATCH 表达式。中文连续区展开为
      （"汉" OR "汉语" ...）OR 词组；其余 token 用引号词。
    expandForIndex(text)：供索引写入，把中文连续区展开为二元词元串，
      其余词汇归一化后原样保留。
    stripPageMarkers(text)：去掉 pdf-parse 追加的 “-- N of M --” 页标记。
  例：查询“律师咨询费怎么收取” → （"律师" OR "师咨" OR "咨询" OR "询费"
    OR "费怎" OR "怎么" OR "么收" OR "收取"）。

3.3  模块 03：storage（src/lib/storage.js，有效 211 行）
--------------------------------------------------------------------------------
  功能：以 node:sqlite（DatabaseSync）封装全部持久化操作，隔离 SQL。
  初始化：PRAGMA journal_mode=WAL；PRAGMA foreign_keys=ON；执行 SCHEMA。
  表结构（详见 3.10）。对外方法：
    listDocs / getDoc / getDocBySha / chunkCount / listChunks / getChunk
    insertDoc / insertChunks（事务） / deleteDoc（事务）
    search(queryText, limit)：FTS5 MATCH + bm25(f) 排序；语法错误时降级
      LIKE 扫描（COLLATE NOCASE）。
    logQuery / listQueryLogs / queryLogStats / getSetting / setSetting / close
  关键点：FTS 虚表在 JOIN + MATCH 下无法安全别名，故先查 fts 取 rowid 与
    原文，再二次联查 chunks/docs 补元数据。

3.4  模块 04：extractors（src/lib/extractors.js，有效 106 行）
--------------------------------------------------------------------------------
  功能：把各格式二进制转为纯文本。
    parseCsv(text)   ：RFC-4180 风格解析（支持引号内逗号/换行/CRLF）。
    extractDocx(buf) ：fflate 解压 zip，读取 word/document.xml，抽取 <w:p>
                       与 <w:t> 文本。
    extractPdf(buf)  ：pdf-parse 抽取文本，剔除乱码字符区（\u0000、\uFFFD）
                       与页标记行。
    textFromBuffer   ：按扩展名分发 .md/.txt/.csv；其他返回 null。
    fileKind / isSupportedFile：扩展名判定（markdown/pdf/docx/csv/text）。

3.5  模块 05：domains（src/lib/domains.js，有效 69 行）
--------------------------------------------------------------------------------
  功能：领域预设话术包。DOMAINS = { legal, medical, procurement, general }。
  每项字段：id、label、greeting、lead、fallback、footer、systemPrompt、
  exampleQuestions。answer() 用 lead/fallback/footer 组装离线回答；可选 LLM
  路径将 systemPrompt 注入 summarizer。getDomain(id) 未命中回退 general。

3.6  模块 06：knowledge（src/lib/knowledge.js，有效 251 行）
--------------------------------------------------------------------------------
  功能：系统核心门面，组合存储、分块、分词、领域模板完成业务。
    ingestBuffer(filename, buffer, meta)：
      未支持的扩展名 → {action:'error'}；查重（sha256）→ duplicate；
      解析文本 → 分块（0 块视为空内容拒绝）→ 插入 docs + chunks → indexed。
    ingestFile / ingestDir：文件路径/目录批量入口（含 seed 用）。
    retrieve(query, limit)：直通 storage.search。
    excerptFrom(body, query, width=160)：在分块内定位首个命中词/二元词组，
      截取周边 width 字符做带省略号的高亮摘录；无命中则取头部。
    answer(query, opts)：离线回答。无命中 → fallback；有命中 →
      lead+摘录+footer；计算 confidence（confidenceScore）与 citations、top。
    answerWithLlm(query, opts)：可选用注入式 summarizer；默认 mockSummarizer。
    logQuery / getQueryLogs / getQueryStats / getSetting / setSetting。
    engineInfo()：对外上报检索能力（fts/bm25/embedding=false/llm=false）。
  离线回答格式：
    answer = lead + “\n\n” + excerpt + “\n\n” + footer。

3.7  模块 07：app（src/app.js，有效 142 行）
--------------------------------------------------------------------------------
  功能：Express 应用工厂 buildApp(kb, opts)，便于测试注入独立实例。
  中间件与路由：
    express.json({limit:'2mb'}) / urlencoded；CORS（反射/允许来源）。
    assertAdmin：RAGDESK_ADMIN_TOKEN 非空时校验 x-admin-token。
    GET  /api/health           引擎状态、领域列表、模式。
    POST /api/chat  （可 Bearer）校验 query；answer + logQuery。
    GET  /api/admin/docs；GET/DELETE /api/admin/docs/:id（404 兜底）；
    POST /api/admin/upload（multer，字段 files，≤20 个，单文件≤50MB）；
    GET  /api/admin/logs、/api/admin/stats；
    GET  /api/domains；
    静态页与 /widget.js、/admin、/。
  统一错误处理：把 multer/body-parser/业务异常映射为 JSON（413/400/500），
  服务端日志仅记录 5xx。

3.8  模块 08：server（src/server.js，有效 45 行）
--------------------------------------------------------------------------------

3.10 数据结构与数据库设计
--------------------------------------------------------------------------------
  docs：
    id PK AUTOINCREMENT；filename；kind；mime；size；sha256 内容指纹查重
    （应用层 getDocBySha 幂等去重，非数据库 UNIQUE）；status DEFAULT 'ready'；
    created_at/updated_at DEFAULT datetime('now')。
  chunks：
    id PK；doc_id REFERENCES docs(id) ON DELETE CASCADE；chunk_idx；body。
    索引 idx_chunks_doc(doc_id)。
  fts（FTS5 虚表）：
    tokens 按 unicode61 分词；orig UNINDEXED（保存原始正文）；
    行 id 与 chunks.id 对齐，保证“索引-原文”一致性。
  queries_log：
    id；query；domain；matched；top_score；top_doc_id；source；created_at。
    索引 idx_queries_created(created_at)。
  settings：
    key PK；value —— 用于 seeded 标记等 KV 配置。

3.11 出错处理设计
--------------------------------------------------------------------------------
  (1) 解析失败：ingestBuffer 捕获异常 → {action:'error', error}，返回前端
      results 数组报告；其他文件照常处理，互不影响。
  (2) 空内容：分块为 0 → 拒绝入库，不残留 docs 孤儿行。
  (3) FTS 语法异常：捕获后降级 LIKE 扫描，保证服务可用。
  (4) 上传超限：multer LIMIT_FILE_SIZE/LIMIT_UNEXPECTED_FILE → 413/400 JSON。
  (5) 不存在的文档：GET/DELETE 返回 404 JSON。
  (6) 请求体过大：express entity.too.large → 413。
  (7) 数据库写事务：BEGIN/COMMIT/ROLLBACK 保证原子性。
  (8) 日志：5xx 打印 console.error；不泄露 token 明文。

3.12 安全保密设计
--------------------------------------------------------------------------------
  (1) 令牌校验：RAGDESK_ADMIN_TOKEN（x-admin-token 请求头）保护 /api/admin/*；
      RAGDESK_CHAT_TOKEN（Authorization Bearer）保护 /api/chat；默认开发态
      为空即开放，生产建议至少设置管理令牌。
  (2) CORS：RAGDESK_ALLOW_ORIGIN 可限制浮窗跨域来源（* 或具体站点）。
  (3) 上传限制：单文件 ≤50MB、单批 ≤20 个、JSON 体 ≤2MB，防滥用。
  (4) 数据驻留：默认无任何外部请求；检索与回答仅操作本地 SQLite。
  (5) 输入清洗：查询经 toQuery 规范化/转义为引号词元，避免 FTS 注入型
      语法错误；LIKE 降级时对 %_ 转义。
  (6) 路径安全：文档名入库前 path.basename 归一，仅存服务端内存缓冲，
      multer memoryStorage 不落盘，杜绝路径穿越。
